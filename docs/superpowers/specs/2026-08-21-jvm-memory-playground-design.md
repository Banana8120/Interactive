# JVM 内存分配 Playground 设计

## 目标

在现有 Docker、Git、MySQL Playground 基础上增加第四个 JVM Playground。模块通过专用终端命令模拟类加载、线程与栈帧、对象和数组分配、引用交互及垃圾回收，并用实时视图展示方法区、线程私有栈和共享堆。

模块只模拟 JVM 内存语义，不解析完整 Java 源码，也不复刻真实 JVM 的对象头、压缩指针、字节对齐、分代或具体垃圾收集器实现。

## 路由与布局

- 顶部导航增加 JVM 入口，路由为 `/jvm`，使用独立紫色主题。
- `JvmPlaygroundView.vue` 最大宽度为 1200px。
- 桌面端采用两列布局：左侧终端，右侧约 460px 的实时内存视图。
- 窄屏切换为上下布局。
- 页面只展示模拟终端和内存交互视图。

## 状态模型

`JvmState` 包含容量、方法区、堆、线程集合、活动线程、对象/线程/栈帧计数器、命令历史和最近一次 GC 统计。

### 方法区

- 总容量为 256 个抽象内存单位。
- 保存已加载类、类常量和静态变量。
- 类只允许加载一次，加载时按命令参数占用容量；该大小代表类信息、常量池和静态变量槽位的完整预留空间，后续定义常量或静态变量不再追加容量。
- 常量只接受数字、布尔值和字符串，定义后不可修改，也不持有模拟堆引用。
- 静态变量可保存数字、布尔值、字符串、`null` 或堆引用。
- 方法区不足时返回 `OutOfMemoryError: Metaspace`，状态不变。
- 首版不实现类卸载，方法区内容不参与 GC。

### 栈内存

- 每个线程拥有独立的 128 单位栈容量。
- 初始状态包含一个空栈的 `main` 线程，并将其设为活动线程。
- 方法区和堆在线程间共享，栈帧不能被其他线程直接访问。
- 每个栈帧包含 id、所属类与方法、占用大小、局部变量表和操作数栈。
- `frame push` 只作用于活动线程，并要求目标类已经加载。
- `frame push` 的类与方法标识按最后一个 `.` 分隔，因此带包名的类名仍可使用。
- 单线程栈容量不足时返回 `StackOverflowError`，其他线程不受影响。
- 弹出栈帧或退出线程会移除其中的 GC Roots，但不会立即删除堆对象。

### 堆内存

- 总容量为 512 个抽象内存单位。
- 对象和数组共享同一容量池，每个条目拥有唯一 id。
- 对象保存类名、大小和字段；创建对象前要求对应类已经加载。
- 数组保存元素类型、长度、单元素大小、总大小和元素值。数组总大小等于 2 单位头部加 `长度 × 单元素大小`。
- 引用使用 `@o1`、`@a1` 形式。写入静态变量、局部变量、操作数、对象字段或数组元素前必须验证引用存在。
- 引用数组只接受引用或 `null`；基础类型数组不接受引用。
- 堆分配不足时自动执行一次 GC；仍不足则返回 `OutOfMemoryError: Java heap space`，分配不产生部分状态。

## 值与区域交互

值支持数字、布尔值、带引号字符串、`null` 和堆引用。

- 方法区静态变量、栈帧局部变量、操作数栈、对象字段和引用数组元素可以持有堆引用。
- 方法区和堆由所有线程共享。
- 线程只能通过切换活动线程后操作自己的栈顶帧。
- 所有状态变更先完成参数、容量、目标区域、活动线程、栈帧、数组索引、值类型和引用有效性校验，再原子提交。

## 命令协议

### 类与方法区

```text
class load User 24
const define User MAX 100
static set User current @o1
```

### 线程与栈帧

```text
thread new worker
thread use worker
thread list
thread exit worker
frame push User.run 12
frame pop
local set user @o1
local remove user
operand push @o1
operand pop
```

### 堆

```text
new object User 20
new array ref 5 4
field set @o1 friend @o2
array set @a1 0 @o1
inspect @o1
```

### 系统

```text
status
gc
help
reset
clear
```

命令解析器返回统一结果类型，区分普通输出、错误、清屏和重置请求。终端负责历史记录、上下键、Tab 补全和重置确认；模拟器不直接依赖 Vue 组件。

## 垃圾回收

采用确定性的标记—清除算法。

GC Roots 包含：

- 所有已加载类的静态变量中的堆引用。
- 所有线程、所有栈帧局部变量中的堆引用。
- 所有线程、所有栈帧操作数栈中的堆引用。

标记阶段从 Roots 出发，递归遍历对象字段和引用数组元素。清除阶段删除所有未标记堆条目。不可达循环引用会被回收；从任一 Root 可达的循环引用会保留。

每次 GC 记录触发原因、扫描数量、存活数量、回收数量和释放容量。`gc` 手动触发；堆容量不足时最多自动触发一次，然后重新判断是否能够完成分配。

## 组件边界

- `src/terminal/jvmSimulator.ts`：纯状态机、命令解析、分配、引用校验、GC、重置和 localStorage 持久化。
- `src/components/JvmTerminal.vue`：终端输入输出、补全、历史和重置事件。
- `src/components/JvmMemoryPanel.vue`：容量进度、方法区、线程栈、堆条目、引用高亮和 GC 统计。
- `src/views/JvmPlaygroundView.vue`：固定状态作用域恢复、终端与面板接线、状态保存和重置确认。
- `src/types/index.ts`：增加 JVM 状态、值、类、线程、栈帧、堆条目和 GC 类型。

持久化键为 `jvm-sim-state-v1-jvm-playground`。恢复旧或不完整数据时使用规范化函数补齐默认字段；非法缓存不会覆盖初始状态。

## 可视化交互

- 顶部显示方法区、活动线程栈和堆的已用量与总容量。
- 方法区按类展示容量、常量和静态变量。
- 栈区域按线程分组，活动线程高亮，栈帧按栈顶到栈底展示局部变量表和操作数栈。
- 堆区域以卡片展示对象或数组的 id、类型、大小、字段或元素。
- 点击任何 `@引用` 会选中并高亮对应堆条目。
- 最近一次 GC 显示扫描、存活、回收和释放容量。

## 错误处理

- 未知命令返回帮助提示，不改变状态。
- 重复类、重复常量、重复线程、缺少活动线程、空栈、非法引用、非法数组索引、非法值类型和无效大小均返回明确错误。
- 方法区、线程栈和堆分别执行独立容量校验。
- 命令失败时不写入历史以外的业务状态，也不保存部分分配结果。
- 重置操作需要用户确认，确认后清理 JVM Playground 缓存并恢复默认状态。

## 测试与验证

增加 Vitest 和 `npm run test`，覆盖：

- 方法区、堆、不同线程栈的容量隔离。
- 类加载、常量不可变、静态变量引用。
- 多线程栈帧隔离和活动线程切换。
- 对象、基础类型数组、引用数组的分配与写入校验。
- `Metaspace` OOM、`StackOverflowError` 和堆 OOM 的原子失败。
- 静态引用、局部变量和操作数作为 GC Roots。
- 不可达循环引用被回收、可达循环引用保留。
- 堆不足时自动 GC 后重试一次。
- 持久化保存、恢复、非法缓存回退和重置。

同时运行 `npm run type-check`、`npm run build`，检查 `/jvm` 路由、导航激活、响应式布局和生产预览资源。
