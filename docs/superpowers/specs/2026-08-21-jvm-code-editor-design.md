# JVM 代码编辑器与内存映射设计

## 背景与目标

当前 JVM Playground 左侧使用专用命令终端。用户需要将其改造成代码编辑器：在左侧编写简化 Java 源码，右侧展示源码执行到当前光标行时对应的方法区、线程栈和堆内存。

第一版聚焦 JVM 内存教学，不实现完整 Java 编译器。它需要稳定展示以下关系：

- 类信息、常量和静态变量进入线程共享的方法区。
- 每个线程拥有独立虚拟机栈，栈帧保存局部变量。
- 对象和数组进入线程共享的堆。
- 静态变量和活动栈帧中的引用作为 GC Root。
- 手动或内存压力触发的标记-清除 GC 回收不可达对象。

## 第一版范围

### 支持的源码结构

第一版支持：

- 多个 `class` 声明。
- 类常量、静态字段和实例字段。
- 一个 `static void main()` 入口。
- 基本类型、`String`、对象引用和数组引用。
- 局部变量声明与赋值。
- 对象创建、数组创建、字段赋值和数组元素赋值。
- 教学用多线程块 `thread <name> { ... }`。
- 手动垃圾回收语句 `gc();`。
- 单行注释 `// ...`。

第一版不支持：

- 自定义方法调用、参数和返回值。
- `if`、`switch`、循环和递归。
- 继承、接口、泛型、注解、包和导入。
- 异常、同步、真实 Java 标准库、文件、网络或本机 JVM。
- 完整 Java 运算符和复杂表达式求值。

### 示例源码

```java
class User {
    static final String TYPE = "member";
    static User current;

    int id;
    String name;
}

class Main {
    static void main() {
        User user = new User();
        user.id = 1;
        user.name = "Alice";

        int[] scores = new int[3];
        scores[0] = 100;

        User.current = user;

        thread worker {
            User copy = new User();
        }

        gc();
    }
}
```

## 语法和类型规则

解析器接受常规换行和缩进，语句使用分号结束。花括号可以与声明同行或独占一行。

支持的值包括：

- 数字字面量。
- `true`、`false`。
- 双引号字符串。
- `null`。
- 当前可见作用域中的局部变量。
- 已声明类的静态字段，格式为 `ClassName.field`。
- 当前作用域内对象的字段，格式为 `variable.field`。
- 数组元素，格式为 `variable[index]`。

支持的声明和语句包括：

```java
static final String NAME = "demo";
static User current;
int id;

int count = 1;
User user = new User();
User[] users = new User[2];
int[] scores = new int[3];

count = 2;
user.id = count;
User.current = user;
users[0] = user;
scores[0] = 100;
gc();
```

字段和数组赋值必须满足已声明类型。引用只能指向兼容对象、兼容引用数组或 `null`。未声明变量、重复声明、未知类、非法索引和类型不匹配都产生行级诊断。

## 执行时刻与光标规则

页面把光标所在行视为目标执行行：

1. 每次源码变化或光标行变化，等待约 300ms。
2. 解析完整源码，建立类、字段、入口和语句模型。
3. 从全新 JVM 状态开始，初始化方法区和静态字面量。
4. 按运行顺序执行 `main()`，直到目标行执行完成。
5. 将该时刻的不可变内存快照交给右侧视图。

“运行全部”把目标行设置为最后一个可执行语句。“重置”经确认后恢复内置示例。“格式化”只整理首尾空白和花括号缩进，不改写变量名或语句。

如果光标位于空行、注释、声明头或右花括号，使用它之前最近一个可执行时刻。如果光标行不在 `main()` 的执行路径中，编辑器显示提示，并使用最近的可达快照。

## 多线程执行规则

`thread worker { ... }` 是教学语法，不是完整 Java 线程 API。

- 进入块时创建命名线程和一个线程入口栈帧。
- 块内局部变量只存在于该线程的栈帧中。
- 方法区和堆与 `main` 线程共享。
- 光标位于线程块内部时，右侧同时显示 `main` 和工作线程的活动栈帧。
- 执行越过线程块右花括号后，工作线程栈帧弹出；线程条目保留为空栈，便于观察生命周期结果。
- 工作线程栈帧弹出后，其中独占的堆引用不再是 GC Root。
- 第一版按源码顺序确定性执行线程块，不模拟调度竞争。

## 内存大小模型

所有容量继续使用抽象内存单位，并采用确定性规则自动推导，不要求用户填写大小。

- 方法区类信息：基础 8 单位，每个常量、静态字段或实例字段增加 2 单位。
- 栈帧：基础 12 单位，每个已经声明的局部变量增加 2 单位。
- 对象：基础 8 单位，再加全部实例字段槽位；`boolean` 为 1，`int`/`float` 为 4，`long`/`double` 为 8，字符串或引用槽为 4。
- 数组：头部 2 单位，加长度乘以元素槽位大小。

方法区、堆和每线程栈继续执行容量检查。失败分配不会修改已有内存。堆分配空间不足时先自动执行一次 GC，仍不足则产生 `OutOfMemoryError`。线程栈超过容量时产生 `StackOverflowError`。

## 界面设计

页面总宽度保持 1200px：

- 左侧为弹性宽度代码编辑器。
- 右侧为 460px JVM 内存面板。
- 小于 1000px 时切换为单列，编辑器在上，内存面板在下。

编辑器包含：

- 标题栏和当前状态。
- 行号栏。
- 基础 Java 关键词、字符串、数字和注释高亮。
- 当前执行行背景。
- 错误行标记和中文诊断信息。
- “运行全部”“格式化”“重置”按钮。

首版使用轻量编辑器实现，不引入 Monaco。编辑器负责文本、光标和滚动同步；解析器不依赖 Vue 或 DOM。

右侧继续复用 `JvmMemoryPanel.vue`，展示：

- 方法区容量、类、常量和静态变量。
- 按线程分组的栈及当前栈帧。
- 堆对象、数组和引用。
- 最近一次 GC 的扫描、存活、回收和释放统计。
- 点击引用后定位并高亮目标堆条目。

## 组件和模块边界

### `JvmCodeEditor.vue`

负责源码输入、行号、高亮覆盖层、光标行、工具栏、诊断展示和事件发送。它不直接分配 JVM 内存。

### `jvmSourceParser.ts`

把源码转换为带源代码行号的类、字段和语句模型，并返回结构化诊断。解析器是纯 TypeScript 模块，不读写全局状态。

### `jvmSourceExecutor.ts`

接收解析结果和目标行，从空状态确定性执行，返回：

- `JvmState` 快照。
- 实际停止行。
- 执行状态。
- 运行期诊断。

内存分配、容量检查、引用校验和 GC 逻辑从现有 `jvmSimulator.ts` 复用或抽取为内部内存引擎。旧命令解析接口不再用于页面。

### `JvmPlaygroundView.vue`

负责编辑器、执行器、内存面板和持久化之间的数据流。页面使用防抖避免每次按键都立即重建状态。

### `JvmMemoryPanel.vue`

继续作为只读内存快照视图。必要时增加当前执行行或运行状态提示，但不修改内存状态。

## 数据与持久化

编辑器源码使用独立 key：

```text
jvm-editor-source-v1-jvm-playground
```

内存状态完全由源码和目标行推导，不单独持久化。旧的 `jvm-sim-state-v1-jvm-playground` 缓存不再恢复，并在用户执行重置时清理。

刷新页面时恢复源码，默认目标为最后一个可执行语句。若源码存在错误，保留原文并显示诊断，不使用默认示例覆盖用户内容。

## 错误处理和原子性

诊断包含阶段、行号和中文信息：

- 语法错误：缺少分号、花括号不匹配或不支持的结构。
- 名称错误：未声明变量、类、字段或线程名重复。
- 类型错误：赋值类型不兼容或数组元素类型错误。
- 运行错误：空引用、非法索引、方法区/堆/栈溢出。

执行器在每次刷新时从空状态重建。发生错误时停止在错误语句之前，返回最后一个完整快照；错误语句不得留下半创建对象、半写入字段或已经增加的计数器。

## 测试与验收

Vitest 单元测试至少覆盖：

- 类、常量、静态字段和实例字段解析。
- `main()` 入口与局部变量作用域。
- 对象、基本类型数组和引用数组分配。
- 局部、字段、静态和数组赋值。
- 光标目标行之前和之后的快照差异。
- 工作线程栈隔离和共享堆访问。
- 栈帧退出后 GC Root 消失。
- 手动 GC、自动 GC 和循环引用回收。
- 类型错误、非法索引、未知名称和容量错误的原子性。
- 源码持久化与无效源码保留。

完成后运行：

```bash
npm run test
npm run type-check
npm run build
```

验收时应能在左侧修改默认示例，并在停止输入或移动光标后看到右侧方法区、对应线程栈和堆结构同步变化；源码错误必须定位到行且不能污染最后有效内存快照。
